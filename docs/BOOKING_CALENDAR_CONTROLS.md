# Booking calendar and account controls

Owner-requested changes, November 2, 2026. Production target remains the native Cloudflare Worker at hiramshot.com.

- Client portal and booking details offer Cancel booking before signing/release. The confirmation explains the effect on equipment and that refunds are handled separately. Ownership and allowed state are checked on the server; cancellation releases exact-time and legacy day holds atomically.
- The admin Bookings and private detail views offer Delete / archive request. It requires the administrator allowlist, current MFA, a reason and the booking reference. Only unpaid, unsigned pre-release requests can be archived. The record is cancelled and removed from the active list, while audit history remains. Archived records can be restored to the list as cancelled requests; restoration never recreates a reservation. Signed/active/paid records are retained. Existing Clients controls handle account restrictions.
- Booking availability shows available, partly booked and fully unavailable days. Full days cannot be selected as a pickup through the calendar; typed dates and exact times are checked through the same physical-unit lookup before submission. The API rechecks independently, and existing transactional reservation overlap triggers remain the final confirmation guard. Pending requests do not consume inventory. Standard and Fly More share the same physical Neo 2. Maintenance and overdue units remain unavailable; legacy day holds cover the return day's occupied hours too.
- The admin Calendar tab shows a monthly fleet view and daily agenda, with confirmed/out rentals separated from pending requests and links to private booking details. Overdue gear stays blocked until returned. All displayed times use Asia/Manila. The calendar API requires staff/admin MFA; public availability contains only anonymous equipment capacity and day states.
- Every header checks a minimal session summary and shows the signed-in name and email, with client portal, email setup and logout in its menu. Anonymous visitors see Log in. The summary omits private profile and verification fields. The duplicate portal greeting was removed.
- Neo 2 Standard / Fly More cards are explicit hover, keyboard and tap preview controls. Fly More uses the owner's supplied IMG_0493 photo, including RC and extra batteries, optimized as neo-flymore.webp. The mobile preview changes too. Hero Pause page motion and See the gear in motion controls were removed; OS reduced-motion support and manual video controls remain.
- Owner alerts remain configured for hiramshotcamerarentals@gmail.com for new registrations, rental requests and complete clean verification submissions. No IDs or billing documents are attached to email. The setup TEST was accepted by the existing email service; acceptance is not proof of Gmail inbox placement.

Migration 0013 adds reversible archive fields, an archive index and guards against archived paid/signed records, new payments on archived requests and reactivating an archived request. It does not delete booking or payment rows. Archiving schedules unpaid request documents for the existing private purge process after seven days, respecting any earlier deletion already scheduled.

Validation: 67 unit/integration tests, 22 component checks, 10 account-verification checks, 6 booking-control API/database checks and the booking-price API check passed. New checks cover ownership, MFA, paid-history protection, archive/restore, privacy of availability data, exact return boundaries, shared units, legacy holds, transactional overlap rejection and complete rollback of multi-unit conflicts. No real customer booking was cancelled or archived for testing. Separate uncommitted QA work and migration 0011 are excluded from this release.
